# EIMS 追加機能設計書 初版

## 1. 追加機能一覧

| No. | 追加機能 | 主な内容 |
| --- | --- | --- |
| 1 | ログイン／ログアウト機能 | ログイン画面、入力チェック、認証、セッション管理、ログアウト |
| 2 | デザイン改良 | 共通レイアウト、Bootstrap 調整、検索結果の見やすさ改善、一覧画面に顔写真表示 |
| 3 | 退職者管理 | `deleteFlg` による論理削除、退職者一覧、復元、完全削除 |
| 4 | 権限による画面制御 | `role` による管理者／一般ユーザーの表示・操作制御 |
| 5 | 詳細画面及び画面遷移改善 | ログイン中社員名リンク、詳細画面の顔写真・権限・退職状態表示、変更・削除ボタン制御 |

## 2. 実装順序と依存関係

共通機能の演習ガイドに沿った実装が完了している状態から開始する。

一部の追加機能は、他の追加機能に依存する。
依存する機能が未実装の場合は、該当箇所を省略して実装してよい。

| 追加機能 | 単独実装 | 依存する機能 |
| --- | --- | --- |
| ログイン／ログアウト | 可能 | なし |
| デザイン改良 | 可能 | なし。ただしログイン表示や権限メニューは他機能と結合時に対応する |
| 退職者管理 | 可能 | なし。ただし管理者限定にする場合はログイン／権限が必要 |
| 権限による画面制御 | 不可 | ログイン／ログアウト機能が必要 |
| 詳細画面及び画面遷移改善 | 一部可能 | ログイン中社員名リンクはログイン、ボタン制御は権限、退職状態表示は退職者管理が必要 |

## 3. 分担実装の進め方

複数人で同時に実装する場合は、各担当が単独で進められる範囲を先に実装し、依存する部分は結合時に追加する。

| 追加機能 | 先に進められる範囲 | 結合時に合わせる範囲 |
| --- | --- | --- |
| ログイン／ログアウト | ログイン画面、認証、セッション保存、ログアウト | 共通レイアウトのヘッダー表示、権限判定、退職者ログイン不可 |
| デザイン改良 | 共通レイアウト、一覧・検索結果の表、一覧画面の顔写真表示 | ログイン状態表示、管理者メニュー、退職状態・権限表示 |
| 退職者管理 | `deleteFlg`、退職者一覧、復元、完全削除 | 管理者だけにメニューや操作を表示する制御 |
| 権限による画面制御 | `role`、管理者／一般ユーザー判定 | ログイン中社員情報、退職者管理、詳細画面の操作ボタン |
| 詳細画面及び画面遷移改善 | 詳細画面の顔写真、権限・退職状態表示 | ログイン中社員名リンク、本人判定、変更・削除ボタン制御 |

同じ画面を複数の担当者が変更する場合は、次の順で結合すると確認しやすい。

1. ログイン情報をセッションに保存できる状態にする。
2. 共通レイアウトを各画面へ適用する。
3. 退職者管理の `deleteFlg` を画面表示と検索条件に反映する。
4. 権限管理の `role` をメニューと操作ボタンに反映する。
5. 詳細画面に、ログイン中社員リンク、顔写真、権限、退職状態、操作ボタン制御を反映する。

画面レイアウト図は、該当機能だけを実装した段階と、他機能を追加した後の段階を分けて確認する。
特に追加機能2は、追加機能3や4を実装する前後で表示項目が変わる。

# 追加機能1 ログイン／ログアウト機能

## 1.1 機能概要

社員番号とパスワードを使ってログインできるようにする。
ログイン成功時は、ログイン中の社員情報をセッションに保持する。
ログアウト時はセッションを破棄し、ログイン画面へ戻る。

## 1.2 実装範囲

- ログイン画面を表示する
- 社員番号とパスワードの入力チェックを行う
- DB上の社員情報と照合して認証する
- ログイン成功時にセッションへログイン社員情報を保存する
- ログイン失敗時にエラーメッセージを表示する
- ログアウト時にセッションを破棄する

## 1.3 前提条件・依存関係

この機能は単独で実装可能である。

ただし、以下の追加機能ではログイン情報を利用するため、この機能が前提になる。

| 関連する追加機能 | 関係 |
| --- | --- |
| 権限による画面制御 | ログイン中社員の `role` を使って管理者かどうか判定する |
| 退職者管理 | 退職済み社員をログイン不可にする場合、`deleteFlg` を参照する |
| デザイン改良 | 共通レイアウトのヘッダーにログイン状態を表示する |
| 詳細画面及び画面遷移改善 | ヘッダーのログイン中社員名から本人詳細へ遷移する |

## 1.4 画面仕様

### ログイン画面

| 項目 | 内容 |
| --- | --- |
| 社員番号 | 数値入力 |
| パスワード | パスワード入力 |
| ログインボタン | 入力内容を送信する |
| エラー表示 | 入力チェックエラー、または認証失敗時に表示する |

### ログイン後の表示

ログイン成功後は、共通レイアウトのヘッダー右上にログイン中社員の氏名を表示する。
表示形式は「ようこそ、氏名さん」とし、氏名の横にログアウトボタンを配置する。

ログアウトボタンを押すとログアウト処理を行い、セッションを破棄してログイン画面へ戻る。

デザイン改良の共通レイアウトをまだ実装していない段階では、ヘッダー右上の表示は作成できない。
その場合は、ログアウト処理だけを先に実装し、共通レイアウト結合時にヘッダー表示とボタン配置を追加する。

### 画面レイアウト図

![ログイン画面](./images/AF01_login.png)

![ログインエラー表示](./images/AF01_login_error.png)

![ログイン後のユーザー名表示とログアウトボタン](./images/AF11_header_logout.png)

## 1.5 処理仕様

### ログイン処理

1. 社員番号とパスワードを受け取る。
2. 入力チェックを行う。
3. 社員番号で社員情報を取得する。
4. パスワードが一致するか確認する。
5. 退職者管理を実装している場合は、`deleteFlg = 0` の社員のみログイン可とする。
6. 認証成功時は、社員情報をセッションに保存してトップページへ遷移する。
7. 認証失敗時は、ログイン画面へ戻し、エラーを表示する。

### ログアウト処理

1. ログアウト操作を受け取る。
2. セッションを破棄する。
3. ログイン画面へリダイレクトする。

## 1.6 データ仕様

この機能単独では、新しいテーブルや列は必須ではない。
既存の社員番号とパスワードを利用する。

退職者管理と結合する場合は、社員情報の `deleteFlg` を参照する。
権限管理と結合する場合は、社員情報の `role` をセッション上でも参照できるようにする。

## 1.7 他機能と結合する場合の追加対応

| 結合する機能 | 追加対応 |
| --- | --- |
| デザイン改良 | 共通レイアウトのヘッダーにログイン中社員名、ログアウトボタン、未ログイン時のログインボタンを表示する |
| 権限による画面制御 | ログイン成功時に保存した社員情報の `role` を使って表示制御する |
| 退職者管理 | `deleteFlg = 1` の社員はログイン失敗扱いにする |
| 詳細画面及び画面遷移改善 | ヘッダーのログイン中社員名を本人詳細画面へのリンクにする |

## 1.8 完了条件

- 正しい社員番号とパスワードでログインできる
- 誤った社員番号またはパスワードではログインできない
- 入力チェックエラーが画面に表示される
- ログイン成功後、セッションにログイン社員情報が保存される
- ログアウト後、セッションが破棄される

## 1.9 テスト観点

| 観点 | 確認内容 |
| --- | --- |
| 正常系 | 正しい社員番号とパスワードでログインできる |
| 異常系 | 未入力、桁不足、不一致時にログイン画面へ戻る |
| セッション | ログイン後にログイン社員情報を参照できる |
| ログアウト | ログアウト後にログイン画面へ戻る |
| 結合 | 権限管理やヘッダー表示でログイン社員情報を利用できる |

# 追加機能2 デザイン改良

## 2.1 機能概要

画面全体の見た目と使いやすさを改善する。
共通レイアウトを導入し、ヘッダー、サイドバー、メイン領域の構成をそろえる。
検索結果や一覧画面では、社員情報を見やすく表示する。

## 2.2 実装範囲

- 共通レイアウトを作成する
- 各画面に共通レイアウトを適用する
- Bootstrap を使って画面の余白、表、ボタンを整える
- 検索結果や一覧画面をレスポンシブ対応にする
- 一覧画面に、社員番号に対応する顔写真を表示する

## 2.3 前提条件・依存関係

この機能は単独で実装可能である。

ただし、他の追加機能と結合する場合は、共通レイアウト内に表示制御を追加する。

| 関連する追加機能 | 関係 |
| --- | --- |
| ログイン／ログアウト | ヘッダーにログイン状態を表示する |
| 権限による画面制御 | サイドバーの管理者用メニューを表示制御する |
| 退職者管理 | 退職者管理メニューを追加する |
| 詳細画面及び画面遷移改善 | 詳細画面にも顔写真を表示する |

## 2.4 画面仕様

### 共通レイアウト

| 領域 | 内容 |
| --- | --- |
| ヘッダー | システム名、ログイン状態表示 |
| サイドバー | トップ、社員検索、社員登録などのメニュー |
| メイン領域 | 各画面の内容を表示する |

ログイン機能を実装していない場合、ヘッダーのログイン状態表示は省略してよい。

### 画面レイアウト図

追加機能2だけを実装した段階では、権限や退職状態の概念がまだない。
そのため、権限列、状態列、退職者管理メニューは表示しない。

![追加機能2のみの社員一覧画面](./images/AF20_design_only_list.png)

### 検索結果・一覧画面

検索結果や社員一覧は、表形式で表示する。

表示項目の例は次の通りとする。

- 顔写真
- 社員番号
- 氏名
- フリガナ
- 部署
- 操作ボタン

操作ボタンは、権限管理を実装している場合のみ表示制御する。

### 他機能を追加した後の画面変化

追加機能3の退職者管理を追加すると、在籍／退職の状態表示や退職者管理の導線が追加される。
ただし、権限管理をまだ実装していない段階では、権限列は表示しない。

![追加機能3追加後の社員一覧画面](./images/AF23_after_retiree_list.png)

追加機能4の権限による画面制御を追加すると、権限表示と管理者向けメニューの表示制御が追加される。

![追加機能4追加後の社員一覧画面](./images/AF24_after_role_list.png)

追加機能5の詳細画面及び画面遷移改善を追加すると、詳細画面に顔写真、権限、退職状態、権限に応じた操作ボタンが表示される。

![追加機能5追加後の社員詳細画面](./images/AF25_after_detail.png)

### 補足

Bootstrap を使う場合は、公式ドキュメントを参照して、既存のクラス名を組み合わせて画面を整える。

| 用途 | 参照先 |
| --- | --- |
| Bootstrap 全体 | [Bootstrap 公式ドキュメント](https://getbootstrap.com/docs/5.3/getting-started/introduction/) |
| 余白や間隔 | [Spacing utilities](https://getbootstrap.com/docs/5.3/utilities/spacing/) |
| サイドバーとメイン領域の横並び | [Grid system](https://getbootstrap.com/docs/5.3/layout/grid/) |
| 権限や状態のラベル表示 | [Badges](https://getbootstrap.com/docs/5.3/components/badge/) |
| 見出しやメニューのアイコン | [Bootstrap Icons](https://icons.getbootstrap.com/) |

## 2.5 処理仕様

### 共通レイアウト適用

1. 共通レイアウトを作成する。
2. 各画面の本文部分を共通レイアウトに差し込む。
3. 画面ごとの差分は、メイン領域に記述する。

### 顔写真表示

顔写真は、あらかじめ静的ファイルとして用意されている画像を表示する。

画像ファイルは、`src/main/resources/static/images` フォルダに配置する。
このフォルダには、社員番号と同じファイル名の PNG 画像が 60 件入っている。

ファイル名の例は次の通りである。

| 社員番号 | 画像ファイル |
| --- | --- |
| 10001 | `/images/10001.png` |
| 10002 | `/images/10002.png` |
| 10060 | `/images/10060.png` |

一覧画面に顔写真を表示する際は、行の高さが大きく崩れないように固定サイズを指定する。
検索結果や一覧画面では、幅 60px、高さ 70px 程度を目安とする。

## 2.6 データ仕様

この機能単独では、新しいDB項目は不要である。

顔写真はDBではなく、静的ファイルとして管理する。
画像ファイルは `src/main/resources/static/images` フォルダに配置する。
ファイル名は社員番号と同じ値にし、拡張子は `.png` とする。

例:

- `10001.png`
- `10002.png`
- `10060.png`

## 2.7 他機能と結合する場合の追加対応

| 結合する機能 | 追加対応 |
| --- | --- |
| ログイン／ログアウト | ヘッダーに「ようこそ、氏名さん」とログアウトボタンを表示する |
| 権限による画面制御 | 管理者のみ、全社員一覧や退職者管理メニューを表示する |
| 退職者管理 | 退職者一覧画面にも共通レイアウトを適用する |
| 詳細画面及び画面遷移改善 | 詳細画面にも社員番号に対応する顔写真を表示する |

## 2.8 完了条件

- 共通レイアウトが適用されている
- 主要画面の見た目が統一されている
- 検索結果や一覧画面が見やすく表示される
- 顔写真が社員番号に対応して表示される
- 画面幅が変わっても表示が大きく崩れない

## 2.9 テスト観点

| 観点 | 確認内容 |
| --- | --- |
| レイアウト | 各画面でヘッダー、サイドバー、メイン領域が表示される |
| 表示 | 検索結果や一覧が表形式で見やすく表示される |
| 画像 | 社員番号に対応した顔写真が表示される |
| レスポンシブ | 画面幅を変えても大きく崩れない |
| 結合 | ログイン状態や権限に応じたメニュー表示ができる |

# 追加機能3 退職者管理

## 3.1 機能概要

社員削除を物理削除ではなく論理削除に変更する。
退職者は通常の検索結果や在籍者一覧には表示せず、退職者一覧で確認できるようにする。
退職者一覧では、復元と完全削除を行えるようにする。

## 3.2 実装範囲

- 社員情報に退職者フラグを追加する
- 削除処理を論理削除に変更する
- 通常検索では退職者を除外する
- 退職者一覧を表示する
- 退職者を在籍者へ復元する
- 退職者を完全削除する

## 3.3 前提条件・依存関係

この機能は単独で実装可能である。

ただし、管理者だけが退職者管理を行えるようにする場合は、ログイン／権限機能が必要である。

| 関連する追加機能 | 関係 |
| --- | --- |
| ログイン／ログアウト | 退職済み社員をログイン不可にする場合に利用する |
| 権限による画面制御 | 退職者一覧、復元、完全削除を管理者のみ操作可能にする |
| デザイン改良 | 退職者一覧に共通レイアウトを適用する |
| 詳細画面及び画面遷移改善 | 詳細画面に退職状態を表示する |

## 3.4 画面仕様

### 退職者一覧画面

| 項目 | 内容 |
| --- | --- |
| 社員番号 | 退職者の社員番号 |
| 氏名 | 姓名、必要に応じてフリガナ |
| 部署 | 所属部署 |
| 復元ボタン | `deleteFlg` を 0 に戻す |
| 完全削除ボタン | DBから物理削除する |

復元と完全削除は、確認画面を設けず、ボタン押下で即時反映してよい。

### 画面レイアウト図

![退職者管理画面](./images/AF03_retiree_list.png)

## 3.5 処理仕様

### 論理削除

1. 削除対象の社員番号を受け取る。
2. 対象社員を取得する。
3. 対象社員の `deleteFlg` を `1` に更新する。
4. 削除完了画面を表示する。

### 通常検索

1. 社員番号、氏名、部署で検索する。
2. 通常検索では `deleteFlg = 0` の社員だけを対象にする。
3. 退職者は通常検索結果に表示しない。

### 退職者一覧

1. `deleteFlg = 1` の社員を取得する。
2. 退職者一覧画面に表示する。

### 復元

1. 復元対象の社員番号を受け取る。
2. 対象社員の `deleteFlg` を `0` に更新する。
3. 退職者一覧へ戻る。

### 完全削除

1. 完全削除対象の社員番号を受け取る。
2. 対象社員をDBから物理削除する。
3. 退職者一覧へ戻る。

## 3.6 データ仕様

社員情報に次の項目を追加する。

| 項目 | 内容 |
| --- | --- |
| `deleteFlg` | 0: 在籍、1: 退職 |

初期値は `0` とする。

## 3.7 他機能と結合する場合の追加対応

| 結合する機能 | 追加対応 |
| --- | --- |
| ログイン／ログアウト | `deleteFlg = 1` の社員はログイン不可にする |
| 権限による画面制御 | 退職者一覧、復元、完全削除を管理者だけに表示・実行させる |
| デザイン改良 | 退職者一覧に共通レイアウトを適用する |
| 詳細画面及び画面遷移改善 | 詳細画面に退職状態を表示する |

## 3.8 完了条件

- 社員削除時にレコードが消えず、`deleteFlg` が `1` になる
- 通常検索に退職者が表示されない
- 退職者一覧に退職者のみ表示される
- 復元すると通常検索に再表示される
- 完全削除するとDBから削除される

## 3.9 テスト観点

| 観点 | 確認内容 |
| --- | --- |
| 論理削除 | 削除後に `deleteFlg` が `1` になる |
| 通常検索 | 退職者が表示されない |
| 退職者一覧 | 退職者のみ表示される |
| 復元 | `deleteFlg` が `0` に戻る |
| 完全削除 | レコードが物理削除される |
| 結合 | 管理者だけが退職者管理を操作できる |

# 追加機能4 権限による画面制御

## 4.1 機能概要

ログイン中の社員の権限に応じて、表示できるメニューや操作ボタンを制御する。
管理者は変更、削除、全社員一覧、退職者管理などの管理操作を行える。
一般ユーザーは参照中心とし、管理操作は行えない。

## 4.2 実装範囲

- 社員情報に権限を追加する
- ログイン中社員の権限を参照する
- 管理者専用メニューを表示制御する
- 検索結果や詳細画面の操作ボタンを表示制御する
- 必要に応じてサーバー側でも操作権限を確認する

## 4.3 前提条件・依存関係

この機能は、ログイン／ログアウト機能が前提である。
ログイン中社員の情報をセッションから参照できない場合、権限判定ができない。

| 関連する追加機能 | 関係 |
| --- | --- |
| ログイン／ログアウト | 必須。ログイン中社員の `role` を参照する |
| デザイン改良 | 共通レイアウトのサイドバーで管理者メニューを制御する |
| 退職者管理 | 退職者管理画面や復元・完全削除を管理者限定にする |
| 詳細画面及び画面遷移改善 | 詳細画面の変更・削除ボタンを権限で出し分ける |

## 4.4 画面仕様

### メニュー表示

| 利用者 | 表示するメニュー |
| --- | --- |
| 未ログイン | ログイン、または基本メニューのみ |
| 一般ユーザー | 検索、登録などの一般機能 |
| 管理者 | 一般機能に加え、全社員一覧、退職者管理など |

### 操作ボタン

| 利用者 | 変更 | 削除 | 退職者管理 |
| --- | --- | --- | --- |
| 一般ユーザー | 原則不可。ただし本人編集を許可する場合あり | 不可 | 不可 |
| 管理者 | 可 | 可 | 可 |

本人編集を許可する場合は、ログイン中社員番号と表示中社員番号が一致するかを条件にする。

### 画面レイアウト図

![一般ユーザーのトップページ](./images/AF04_top_general.png)

![一般ユーザーで他社員詳細を表示した場合](./images/AF04_detail_general_other.png)

## 4.5 処理仕様

### 権限判定

1. ログイン中社員情報をセッションから取得する。
2. `role` を確認する。
3. `role = 1` の場合は管理者と判定する。
4. `role = 0` の場合は一般ユーザーと判定する。

### 表示制御

1. 画面側でログイン中社員の `role` を参照する。
2. 管理者のみ表示するメニューやボタンに表示条件を設定する。
3. 一般ユーザーには管理操作を表示しない。

### サーバー側制御

画面上のボタンを非表示にするだけでは、URL直接入力による操作を防げない。
必要に応じて、Controller 側でも管理者かどうかを確認する。

## 4.6 データ仕様

社員情報に次の項目を追加する。

| 項目 | 内容 |
| --- | --- |
| `role` | 0: 一般ユーザー、1: 管理者 |

初期値は `0` とする。
管理者として利用する社員には `1` を設定する。

## 4.7 他機能と結合する場合の追加対応

| 結合する機能 | 追加対応 |
| --- | --- |
| デザイン改良 | 共通レイアウトのサイドバーで管理者メニューを表示制御する |
| 退職者管理 | 退職者一覧、復元、完全削除を管理者限定にする |
| 詳細画面及び画面遷移改善 | 詳細画面の変更・削除ボタンを管理者／本人条件で制御する |

## 4.8 完了条件

- 管理者でログインした場合、管理者用メニューが表示される
- 一般ユーザーでログインした場合、管理者用メニューが表示されない
- 管理者のみ変更・削除などの操作ボタンが表示される
- 一般ユーザーが管理操作を直接実行できないようにする

## 4.9 テスト観点

| 観点 | 確認内容 |
| --- | --- |
| 管理者表示 | 管理者でログインすると管理者用メニューが表示される |
| 一般表示 | 一般ユーザーでは管理者用メニューが表示されない |
| 操作制御 | 管理者のみ変更・削除ができる |
| 直接アクセス | URL直接入力で不正操作できない |
| 結合 | 退職者管理や詳細画面のボタン表示と連動する |

# 追加機能5 詳細画面及び画面遷移改善

## 5.1 機能概要

共通機能で作成済みの社員詳細画面に、追加表示と画面遷移を加える。

一覧画面や検索結果画面から詳細画面へ遷移するリンクは、共通機能の段階で作成済みである。
この追加機能では、主に次の内容を実装する。

- ヘッダーのログイン中社員名をクリックすると、本人の詳細画面へ遷移する
- 詳細画面に社員番号に対応する顔写真を表示する
- 詳細画面に権限と退職状態を表示する
- 権限に応じて、変更ボタンと削除ボタンの表示を制御する

## 5.2 実装範囲

- ヘッダーに表示しているログイン中社員名をリンクにする
- ログイン中社員名クリック時、本人の詳細画面へ遷移する
- 詳細画面に顔写真を表示する
- 詳細画面に権限を表示する
- 詳細画面に退職状態を表示する
- 詳細画面の変更ボタン、削除ボタンを権限に応じて表示制御する

## 5.3 前提条件・依存関係

この機能は、共通機能で社員詳細画面が作成済みであることを前提とする。
また、一覧画面や検索結果画面から社員詳細画面へのリンクも作成済みであることを前提とする。

| 関連する追加機能 | 関係 |
| --- | --- |
| ログイン／ログアウト | ヘッダーのログイン中社員名リンクに必要 |
| デザイン改良 | 顔写真表示に使用する画像ファイルの配置仕様を利用する |
| 退職者管理 | 詳細画面に退職状態を表示する場合に `deleteFlg` を利用する |
| 権限による画面制御 | 変更・削除ボタンの表示制御に `role` を利用する |

## 5.4 画面仕様

### ヘッダー

ログインしている場合、ヘッダーにログイン中社員名を表示する。
社員名はクリックできるリンクにする。

リンク押下時は、ログイン中社員本人の詳細画面へ遷移する。

例:

```html
<a th:href="@{'/detail/' + ${session.loginEmployee.empNo}}"
   th:text="${session.loginEmployee.lastName + ' ' + session.loginEmployee.firstName}">
</a>
```

### 社員詳細画面

共通機能で作成済みの詳細画面に、次の項目を追加表示する。

| 項目 | 内容 |
| --- | --- |
| 顔写真 | 社員番号に対応する画像 |
| 権限 | `role = 1` の場合は管理者、`role = 0` の場合は一般ユーザー |
| 退職状態 | `deleteFlg = 1` の場合は退職、`deleteFlg = 0` の場合は在籍 |

顔写真は、デザイン改良で使用する画像と同じものを利用する。
画像ファイルは `src/main/resources/static/images` フォルダに配置されており、社員番号と同じファイル名になっている。

例:

| 社員番号 | 画像ファイル |
| --- | --- |
| 10001 | `/images/10001.png` |
| 10060 | `/images/10060.png` |

### 操作ボタン

詳細画面の変更ボタン、削除ボタンは、ログイン中社員の権限に応じて表示を制御する。

| ログイン中社員 | 表示対象社員 | 変更ボタン | 削除ボタン |
| --- | --- | --- | --- |
| 管理者 | 本人 | 表示 | 非表示 |
| 管理者 | 他の社員 | 表示 | 表示 |
| 一般ユーザー | 本人 | 表示 | 非表示 |
| 一般ユーザー | 他の社員 | 非表示 | 非表示 |

管理者本人の削除ボタンは表示しない。
これは、ログイン中の管理者が自分自身を削除してしまう操作を避けるためである。

### 画面レイアウト図

![管理者で他社員詳細を表示した場合](./images/AF05_detail_admin_other.png)

![管理者で本人詳細を表示した場合](./images/AF05_detail_admin_self.png)

## 5.5 処理仕様

### ログイン中社員名リンク

1. セッションからログイン中社員情報を取得する。
2. ヘッダーにログイン中社員名を表示する。
3. 社員名に本人詳細画面へのリンクを設定する。
4. クリック時、ログイン中社員の社員番号を使って詳細画面へ遷移する。

### 詳細画面の追加表示

1. 詳細表示対象の社員情報を取得する。
2. 社員番号を使って顔写真の画像パスを組み立てる。
3. `role` を表示用の文言に変換する。
4. `deleteFlg` を表示用の文言に変換する。
5. 詳細画面に顔写真、権限、退職状態を表示する。

### 操作ボタンの表示制御

1. セッションからログイン中社員情報を取得する。
2. ログイン中社員の `role` を確認する。
3. ログイン中社員番号と表示対象社員番号を比較する。
4. 管理者、本人、他人の条件に応じて、変更ボタンと削除ボタンを表示する。

## 5.6 データ仕様

この機能で新しいDB項目は追加しない。

次の既存項目、または他の追加機能で追加した項目を利用する。

| 項目 | 利用目的 |
| --- | --- |
| `empNo` | 顔写真ファイル名、本人判定、詳細画面遷移 |
| `lastName` / `firstName` | ヘッダー表示 |
| `role` | 権限表示、変更・削除ボタンの表示制御 |
| `deleteFlg` | 退職状態表示 |

## 5.7 他機能と結合する場合の追加対応

| 結合する機能 | 追加対応 |
| --- | --- |
| ログイン／ログアウト | ログイン成功時にセッションへ保存した社員情報を利用する |
| デザイン改良 | 顔写真の配置場所と表示サイズをそろえる |
| 退職者管理 | `deleteFlg` を使って退職状態を表示する |
| 権限による画面制御 | `role` を使って変更・削除ボタンを表示制御する |

## 5.8 完了条件

- ヘッダーのログイン中社員名をクリックすると、本人詳細画面へ遷移できる
- 詳細画面に社員番号に対応する顔写真が表示される
- 詳細画面に権限が表示される
- 詳細画面に退職状態が表示される
- 管理者、本人、他人の条件に応じて、変更・削除ボタンの表示が変わる

## 5.9 テスト観点

| 観点 | 確認内容 |
| --- | --- |
| ヘッダーリンク | ログイン中社員名から本人詳細画面へ遷移できる |
| 顔写真 | 社員番号に対応した画像が詳細画面に表示される |
| 権限表示 | 管理者／一般ユーザーが正しく表示される |
| 退職状態表示 | 在籍／退職が正しく表示される |
| 管理者操作 | 管理者は他の社員の変更・削除ボタンを確認できる |
| 本人操作 | 一般ユーザー本人は変更ボタンのみ確認できる |
| 他人操作 | 一般ユーザーが他人の詳細を表示した場合、変更・削除ボタンが表示されない |
