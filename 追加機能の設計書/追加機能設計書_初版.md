# EIMS 追加機能設計書 初版

## 1. 本書の目的

本書は、EIMS の基本機能が完成している状態から、受講者が追加機能を選択して実装するための設計書である。

通常機能の設計書ほど細かい実装手順は記載せず、次の内容を中心に整理する。

- 何を実装すればよいか
- どこまでできれば完了とみなすか
- 先に実装しておく必要がある機能は何か
- 他の追加機能と組み合わせる場合に、どこを追加で対応するか

5つの追加機能は、すべてを必ず実装する前提ではない。
受講者は、時間内で実装できる機能を選択してよい。

## 2. 追加機能一覧

| No. | 追加機能 | 主な内容 |
| --- | --- | --- |
| 1 | ログイン／ログアウト機能 | ログイン画面、入力チェック、認証、セッション管理、ログアウト |
| 2 | デザイン改良 | 共通レイアウト、Bootstrap 調整、検索結果の見やすさ改善、顔写真表示 |
| 3 | 退職者管理 | `deleteFlg` による論理削除、退職者一覧、復元、完全削除 |
| 4 | 権限による画面制御 | `role` による管理者／一般ユーザーの表示・操作制御 |
| 5 | 詳細画面及び画面遷移改善 | 氏名リンク、ログインユーザー名リンク、詳細画面の操作ボタン制御 |

## 3. 実装順序と依存関係

一部の追加機能は、他の追加機能に依存する。
依存する機能が未実装の場合は、該当箇所を省略して実装してよい。

| 追加機能 | 単独実装 | 依存する機能 |
| --- | --- | --- |
| ログイン／ログアウト | 可能 | なし |
| デザイン改良 | 可能 | なし。ただしログイン表示や権限メニューは他機能と結合時に対応する |
| 退職者管理 | 可能 | なし。ただし管理者限定にする場合はログイン／権限が必要 |
| 権限による画面制御 | 不可 | ログイン／ログアウト機能が必要 |
| 詳細画面及び画面遷移改善 | 一部可能 | ログインユーザー名リンクやボタン制御はログイン／権限が必要 |

## 4. 対象ソース一覧について

本書では、変更対象ソースの一覧は原則として記載しない。

理由は、受講者が選択する追加機能や実装順序によって、実際に編集するファイルが変わるためである。
必要に応じて、Controller、Service、Repository、Entity、Form、HTML のどこに責務を置くかを設計内容から判断する。

## 5. 評価の考え方

評価は「追加機能ごとの完成度」で行う。
すべての追加機能を結合して完成しているかだけではなく、各機能が単独でどこまで動作するかを確認する。

他機能との結合部分は、該当する依存機能を実装した場合のみ評価対象とする。

## 6. 担当別の実装範囲例

チームで作業する場合は、次のように担当を分けると進めやすい。
ただし、実装順序や進捗によって担当範囲を調整してよい。

| 担当 | 内容 |
| --- | --- |
| ログイン・ログアウト担当 | ログイン画面、入力チェック、認証、セッション管理、ログアウト、ログインユーザー名表示 |
| デザイン担当 | 共通レイアウト、検索結果のレスポンシブ対応、一覧・詳細画面の見た目調整、顔写真表示 |
| 権限管理担当 | `role` の追加、管理者／一般ユーザーの表示制御、管理者用メニュー、操作ボタン制御 |
| 画面遷移改善担当 | 一覧・検索結果から詳細画面への遷移、ログインユーザー名クリックによる本人詳細遷移、ログイン画面から登録画面への導線 |
| 退職者管理担当 | `deleteFlg` の追加、論理削除、退職者一覧、復元、完全削除、通常検索からの退職者除外 |

# 追加機能1 ログイン／ログアウト機能

## 1.1 機能概要

社員番号とパスワードを使ってログインできるようにする。
ログイン成功時は、ログイン中の社員情報をセッションに保持する。
ログアウト時はセッションを破棄し、ログイン画面へ戻る。

## 1.2 実装範囲

- ログイン画面を表示する
- 社員番号とパスワードの入力チェックを行う
- DB上の社員情報と照合して認証する
- ログイン成功時にセッションへログイン社員情報を保存する
- ログイン失敗時にエラーメッセージを表示する
- ログアウト時にセッションを破棄する

## 1.3 前提条件・依存関係

この機能は単独で実装可能である。

ただし、以下の追加機能ではログイン情報を利用するため、この機能が前提になる。

| 関連する追加機能 | 関係 |
| --- | --- |
| 権限による画面制御 | ログイン中社員の `role` を使って管理者かどうか判定する |
| 詳細画面及び画面遷移改善 | ヘッダーのログイン社員名から本人詳細へ遷移する |
| 退職者管理 | 退職済み社員をログイン不可にする場合、`deleteFlg` を参照する |
| デザイン改良 | 共通レイアウトのヘッダーにログイン状態を表示する |

## 1.4 画面仕様

### ログイン画面

| 項目 | 内容 |
| --- | --- |
| 社員番号 | 数値入力 |
| パスワード | パスワード入力 |
| ログインボタン | 入力内容を送信する |
| エラー表示 | 入力チェックエラー、または認証失敗時に表示する |
| 新規登録リンク | 詳細画面及び画面遷移改善を実装する場合に配置する |

## 1.5 処理仕様

### ログイン処理

1. 社員番号とパスワードを受け取る。
2. 入力チェックを行う。
3. 社員番号で社員情報を取得する。
4. パスワードが一致するか確認する。
5. 退職者管理を実装している場合は、`deleteFlg = 0` の社員のみログイン可とする。
6. 認証成功時は、社員情報をセッションに保存してトップページへ遷移する。
7. 認証失敗時は、ログイン画面へ戻し、エラーを表示する。

### ログアウト処理

1. ログアウト操作を受け取る。
2. セッションを破棄する。
3. ログイン画面へリダイレクトする。

## 1.6 データ仕様

この機能単独では、新しいテーブルや列は必須ではない。
既存の社員番号とパスワードを利用する。

退職者管理と結合する場合は、社員情報の `deleteFlg` を参照する。
権限管理と結合する場合は、社員情報の `role` をセッション上でも参照できるようにする。

## 1.7 他機能と結合する場合の追加対応

| 結合する機能 | 追加対応 |
| --- | --- |
| デザイン改良 | 共通レイアウトのヘッダーにログイン中社員名、ログアウトボタン、未ログイン時のログインボタンを表示する |
| 権限による画面制御 | ログイン成功時に保存した社員情報の `role` を使って表示制御する |
| 詳細画面及び画面遷移改善 | ヘッダーの社員名をクリックできるリンクにする |
| 退職者管理 | `deleteFlg = 1` の社員はログイン失敗扱いにする |

## 1.8 完了条件

- 正しい社員番号とパスワードでログインできる
- 誤った社員番号またはパスワードではログインできない
- 入力チェックエラーが画面に表示される
- ログイン成功後、セッションにログイン社員情報が保存される
- ログアウト後、セッションが破棄される

## 1.9 テスト観点

| 観点 | 確認内容 |
| --- | --- |
| 正常系 | 正しい社員番号とパスワードでログインできる |
| 異常系 | 未入力、桁不足、不一致時にログイン画面へ戻る |
| セッション | ログイン後にログイン社員情報を参照できる |
| ログアウト | ログアウト後にログイン画面へ戻る |
| 結合 | 権限管理やヘッダー表示でログイン社員情報を利用できる |

# 追加機能2 デザイン改良

## 2.1 機能概要

画面全体の見た目と使いやすさを改善する。
共通レイアウトを導入し、ヘッダー、サイドバー、メイン領域の構成をそろえる。
検索結果や一覧画面では、社員情報を見やすく表示する。

## 2.2 実装範囲

- 共通レイアウトを作成する
- 各画面に共通レイアウトを適用する
- Bootstrap を使って画面の余白、表、ボタンを整える
- 検索結果や一覧画面をレスポンシブ対応にする
- 社員番号に対応する顔写真を表示する

## 2.3 前提条件・依存関係

この機能は単独で実装可能である。

ただし、他の追加機能と結合する場合は、共通レイアウト内に表示制御を追加する。

| 関連する追加機能 | 関係 |
| --- | --- |
| ログイン／ログアウト | ヘッダーにログイン状態を表示する |
| 権限による画面制御 | サイドバーの管理者用メニューを表示制御する |
| 退職者管理 | 退職者管理メニューを追加する |
| 詳細画面及び画面遷移改善 | ヘッダーの社員名リンクや詳細画面の見た目を整える |

## 2.4 画面仕様

### 共通レイアウト

| 領域 | 内容 |
| --- | --- |
| ヘッダー | システム名、ログイン状態表示 |
| サイドバー | トップ、社員検索、社員登録などのメニュー |
| メイン領域 | 各画面の内容を表示する |

ログイン機能を実装していない場合、ヘッダーのログイン状態表示は省略してよい。

### 検索結果・一覧画面

検索結果や社員一覧は、表形式で表示する。

表示項目の例は次の通りとする。

- 顔写真
- 社員番号
- 氏名
- フリガナ
- 部署
- 操作ボタン

操作ボタンは、権限管理を実装している場合のみ表示制御する。

## 2.5 処理仕様

### 共通レイアウト適用

1. 共通レイアウトを作成する。
2. 各画面の本文部分を共通レイアウトに差し込む。
3. 画面ごとの差分は、メイン領域に記述する。

### 顔写真表示

1. 社員番号に対応する画像ファイルを参照する。
2. 画像が表示されるように、固定サイズを指定する。
3. 画像の代替テキストには社員名を設定する。

## 2.6 データ仕様

この機能単独では、新しいDB項目は不要である。

顔写真はDBではなく、静的ファイルとして管理する。
画像ファイル名は、社員番号に対応させる。

## 2.7 他機能と結合する場合の追加対応

| 結合する機能 | 追加対応 |
| --- | --- |
| ログイン／ログアウト | ヘッダーに「ようこそ、氏名さん」とログアウトボタンを表示する |
| 権限による画面制御 | 管理者のみ、全社員一覧や退職者管理メニューを表示する |
| 退職者管理 | 退職者一覧画面にも共通レイアウトを適用する |
| 詳細画面及び画面遷移改善 | 詳細画面に顔写真と属性表を表示する |

## 2.8 完了条件

- 共通レイアウトが適用されている
- 主要画面の見た目が統一されている
- 検索結果や一覧画面が見やすく表示される
- 顔写真が社員番号に対応して表示される
- 画面幅が変わっても表示が大きく崩れない

## 2.9 テスト観点

| 観点 | 確認内容 |
| --- | --- |
| レイアウト | 各画面でヘッダー、サイドバー、メイン領域が表示される |
| 表示 | 検索結果や一覧が表形式で見やすく表示される |
| 画像 | 社員番号に対応した顔写真が表示される |
| レスポンシブ | 画面幅を変えても大きく崩れない |
| 結合 | ログイン状態や権限に応じたメニュー表示ができる |

# 追加機能3 退職者管理

## 3.1 機能概要

社員削除を物理削除ではなく論理削除に変更する。
退職者は通常の検索結果や在籍者一覧には表示せず、退職者一覧で確認できるようにする。
退職者一覧では、復元と完全削除を行えるようにする。

## 3.2 実装範囲

- 社員情報に退職者フラグを追加する
- 削除処理を論理削除に変更する
- 通常検索では退職者を除外する
- 退職者一覧を表示する
- 退職者を在籍者へ復元する
- 退職者を完全削除する

## 3.3 前提条件・依存関係

この機能は単独で実装可能である。

ただし、管理者だけが退職者管理を行えるようにする場合は、ログイン／権限機能が必要である。

| 関連する追加機能 | 関係 |
| --- | --- |
| ログイン／ログアウト | 退職済み社員をログイン不可にする場合に利用する |
| 権限による画面制御 | 退職者一覧、復元、完全削除を管理者のみ操作可能にする |
| デザイン改良 | 退職者一覧に共通レイアウトを適用する |
| 詳細画面及び画面遷移改善 | 詳細画面の削除ボタンを退職処理として扱う |

## 3.4 画面仕様

### 退職者一覧画面

| 項目 | 内容 |
| --- | --- |
| 社員番号 | 退職者の社員番号 |
| 氏名 | 姓名、必要に応じてフリガナ |
| 部署 | 所属部署 |
| 復元ボタン | `deleteFlg` を 0 に戻す |
| 完全削除ボタン | DBから物理削除する |

復元と完全削除は、確認画面を設けず、ボタン押下で即時反映してよい。

## 3.5 処理仕様

### 論理削除

1. 削除対象の社員番号を受け取る。
2. 対象社員を取得する。
3. 対象社員の `deleteFlg` を `1` に更新する。
4. 削除完了画面を表示する。

### 通常検索

1. 社員番号、氏名、部署で検索する。
2. 通常検索では `deleteFlg = 0` の社員だけを対象にする。
3. 退職者は通常検索結果に表示しない。

### 退職者一覧

1. `deleteFlg = 1` の社員を取得する。
2. 退職者一覧画面に表示する。

### 復元

1. 復元対象の社員番号を受け取る。
2. 対象社員の `deleteFlg` を `0` に更新する。
3. 退職者一覧へ戻る。

### 完全削除

1. 完全削除対象の社員番号を受け取る。
2. 対象社員をDBから物理削除する。
3. 退職者一覧へ戻る。

## 3.6 データ仕様

社員情報に次の項目を追加する。

| 項目 | 内容 |
| --- | --- |
| `deleteFlg` | 0: 在籍、1: 退職 |

初期値は `0` とする。

## 3.7 他機能と結合する場合の追加対応

| 結合する機能 | 追加対応 |
| --- | --- |
| ログイン／ログアウト | `deleteFlg = 1` の社員はログイン不可にする |
| 権限による画面制御 | 退職者一覧、復元、完全削除を管理者だけに表示・実行させる |
| デザイン改良 | 退職者一覧に共通レイアウトを適用する |
| 詳細画面及び画面遷移改善 | 詳細画面の削除ボタンから論理削除へ遷移する |

## 3.8 完了条件

- 社員削除時にレコードが消えず、`deleteFlg` が `1` になる
- 通常検索に退職者が表示されない
- 退職者一覧に退職者のみ表示される
- 復元すると通常検索に再表示される
- 完全削除するとDBから削除される

## 3.9 テスト観点

| 観点 | 確認内容 |
| --- | --- |
| 論理削除 | 削除後に `deleteFlg` が `1` になる |
| 通常検索 | 退職者が表示されない |
| 退職者一覧 | 退職者のみ表示される |
| 復元 | `deleteFlg` が `0` に戻る |
| 完全削除 | レコードが物理削除される |
| 結合 | 管理者だけが退職者管理を操作できる |

# 追加機能4 権限による画面制御

## 4.1 機能概要

ログイン中の社員の権限に応じて、表示できるメニューや操作ボタンを制御する。
管理者は変更、削除、全社員一覧、退職者管理などの管理操作を行える。
一般ユーザーは参照中心とし、管理操作は行えない。

## 4.2 実装範囲

- 社員情報に権限を追加する
- ログイン中社員の権限を参照する
- 管理者専用メニューを表示制御する
- 検索結果や詳細画面の操作ボタンを表示制御する
- 必要に応じてサーバー側でも操作権限を確認する

## 4.3 前提条件・依存関係

この機能は、ログイン／ログアウト機能が前提である。
ログイン中社員の情報をセッションから参照できない場合、権限判定ができない。

| 関連する追加機能 | 関係 |
| --- | --- |
| ログイン／ログアウト | 必須。ログイン中社員の `role` を参照する |
| デザイン改良 | 共通レイアウトのサイドバーで管理者メニューを制御する |
| 退職者管理 | 退職者管理画面や復元・完全削除を管理者限定にする |
| 詳細画面及び画面遷移改善 | 詳細画面の変更・削除ボタンを権限で出し分ける |

## 4.4 画面仕様

### メニュー表示

| 利用者 | 表示するメニュー |
| --- | --- |
| 未ログイン | ログイン、または基本メニューのみ |
| 一般ユーザー | 検索、登録などの一般機能 |
| 管理者 | 一般機能に加え、全社員一覧、退職者管理など |

### 操作ボタン

| 利用者 | 変更 | 削除 | 退職者管理 |
| --- | --- | --- | --- |
| 一般ユーザー | 原則不可。ただし本人編集を許可する場合あり | 不可 | 不可 |
| 管理者 | 可 | 可 | 可 |

本人編集を許可するかどうかは、詳細画面及び画面遷移改善と結合する場合に扱う。

## 4.5 処理仕様

### 権限判定

1. ログイン中社員情報をセッションから取得する。
2. `role` を確認する。
3. `role = 1` の場合は管理者と判定する。
4. `role = 0` の場合は一般ユーザーと判定する。

### 表示制御

1. 画面側でログイン中社員の `role` を参照する。
2. 管理者のみ表示するメニューやボタンに表示条件を設定する。
3. 一般ユーザーには管理操作を表示しない。

### サーバー側制御

画面上のボタンを非表示にするだけでは、URL直接入力による操作を防げない。
必要に応じて、Controller 側でも管理者かどうかを確認する。

## 4.6 データ仕様

社員情報に次の項目を追加する。

| 項目 | 内容 |
| --- | --- |
| `role` | 0: 一般ユーザー、1: 管理者 |

初期値は `0` とする。
管理者として利用する社員には `1` を設定する。

## 4.7 他機能と結合する場合の追加対応

| 結合する機能 | 追加対応 |
| --- | --- |
| デザイン改良 | 共通レイアウトのサイドバーで管理者メニューを表示制御する |
| 退職者管理 | 退職者一覧、復元、完全削除を管理者限定にする |
| 詳細画面及び画面遷移改善 | 詳細画面の変更・削除ボタンを管理者／本人条件で制御する |

## 4.8 完了条件

- 管理者でログインした場合、管理者用メニューが表示される
- 一般ユーザーでログインした場合、管理者用メニューが表示されない
- 管理者のみ変更・削除などの操作ボタンが表示される
- 一般ユーザーが管理操作を直接実行できないようにする

## 4.9 テスト観点

| 一般表示 | 一般ユーザーでは管理者用メニューが表示されない |
| 操作制御 | 管理者のみ変更・削除ができる |

# 追加機能5 詳細画面及び画面遷移改善

## 5.1 機能概要

一覧や検索結果から社員詳細へ遷移しやすくする。
ログイン中社員の氏名をクリックすると、自分の詳細画面へ遷移できるようにする。
詳細画面では、社員情報を見やすく表示し、権限に応じて変更・削除ボタンを出し分ける。

## 5.2 実装範囲

- 検索結果や一覧の氏名を詳細画面へのリンクにする
- 社員詳細画面を表示する
- ヘッダーのログイン社員名を本人詳細へのリンクにする
- 詳細画面に顔写真と属性情報を表示する
- 変更ボタン、削除ボタンを条件に応じて表示する
- ログイン画面から登録画面へ遷移できるリンクを配置する

## 5.3 前提条件・依存関係

この機能は一部だけなら単独実装可能である。

検索結果や一覧から詳細画面へ遷移する機能は、ログインなしでも実装できる。
ただし、ログイン社員名リンクや権限によるボタン制御は、他の追加機能が必要である。

| 関連する追加機能 | 関係 |
| --- | --- |
| ログイン／ログアウト | ヘッダーのログイン社員名リンクに必要 |
| 権限による画面制御 | 変更・削除ボタンの表示制御に必要 |
| デザイン改良 | 詳細画面のレイアウトや顔写真表示に関係する |
| 退職者管理 | 削除ボタンを論理削除として扱う場合に必要 |

## 5.4 画面仕様

### 検索結果・一覧画面

氏名をクリックできるリンクにする。
リンク押下時、対象社員の詳細画面へ遷移する。

### ヘッダー

ログイン機能を実装している場合、ヘッダーのログイン社員名をリンクにする。
リンク押下時、ログイン中社員本人の詳細画面へ遷移する。

### 社員詳細画面

| 項目 | 内容 |
| --- | --- |
| 顔写真 | 社員番号に対応する画像 |
| 社員番号 | 対象社員の社員番号 |
| 氏名 | 姓名 |
| フリガナ | 姓名のカナ |
| 性別 | 男性／女性 |
| 部署 | 所属部署 |
| 権限 | 管理者／一般 |
| 退職状態 | 在籍／退職 |

## 5.5 処理仕様

### 氏名リンク

1. 検索結果または一覧に社員を表示する。
2. 氏名部分に詳細画面へのリンクを設定する。
3. リンク押下時、社員番号を指定して詳細画面を表示する。

### ログイン社員名リンク

1. セッションからログイン中社員情報を取得する。
2. ヘッダーにログイン中社員名を表示する。
3. 社員名を本人詳細画面へのリンクにする。

### 詳細画面の操作ボタン

| 条件 | 変更ボタン | 削除ボタン |
| --- | --- | --- |
| 管理者 | 表示 | 表示 |
| 一般ユーザー本人 | 表示 | 非表示 |
| 一般ユーザー他人 | 非表示 | 非表示 |

削除ボタンは、退職者管理を実装している場合、物理削除ではなく論理削除へつなげる。

## 5.6 データ仕様

この機能単独では、新しいDB項目は必須ではない。

ただし、権限表示を行う場合は `role` を参照する。
退職状態を表示する場合は `deleteFlg` を参照する。

## 5.7 他機能と結合する場合の追加対応

| 結合する機能 | 追加対応 |
| --- | --- |
| ログイン／ログアウト | ヘッダーのログイン社員名を本人詳細へのリンクにする |
| 権限による画面制御 | 変更・削除ボタンを管理者／本人条件で表示制御する |
| 退職者管理 | 削除ボタンから論理削除処理へ遷移する |
| デザイン改良 | 詳細画面に顔写真と表形式レイアウトを適用する |

## 5.8 完了条件

- 検索結果や一覧の氏名から詳細画面へ遷移できる
- 詳細画面に社員情報が表示される
- ログイン中社員名から本人詳細へ遷移できる
- 権限に応じて変更・削除ボタンが表示制御される
- ログイン画面から登録画面へ遷移できる
