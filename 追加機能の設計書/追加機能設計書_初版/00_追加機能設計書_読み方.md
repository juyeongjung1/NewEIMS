# 追加機能設計書 初版

## 目的

この設計書は、EIMS の基本機能が完成している状態から、受講者が追加機能を選択して実装するための資料である。

通常機能の設計書ほど細かい実装手順は書かず、以下を中心に記載する。

- 何を実装すればよいか
- どこまでできれば完了とみなすか
- 他の追加機能と組み合わせる場合に、どこを追加で対応するか
- 先に実装しておく必要がある機能は何か

## 追加機能一覧

| No. | 追加機能 | 主な内容 |
| --- | --- | --- |
| 1 | ログイン／ログアウト機能 | ログイン画面、入力チェック、認証、セッション管理、ログアウト |
| 2 | デザイン改良 | 共通レイアウト、Bootstrap 調整、検索結果の見やすさ改善、顔写真表示 |
| 3 | 退職者管理 | `deleteFlg` による論理削除、退職者一覧、復元、完全削除 |
| 4 | 権限による画面制御 | `role` による管理者／一般ユーザーの表示・操作制御 |
| 5 | 詳細画面及び画面遷移改善 | 氏名リンク、ログインユーザー名リンク、詳細画面の操作ボタン制御 |

## 実装順序の考え方

5つの追加機能は、すべてを必ず実装する前提ではない。
受講者は、時間内で実装できる機能を選択してよい。

ただし、一部の機能は他の追加機能に依存する。

| 追加機能 | 単独実装 | 依存する機能 |
| --- | --- | --- |
| ログイン／ログアウト | 可能 | なし |
| デザイン改良 | 可能 | なし。ただしログイン表示や権限メニューは他機能と結合時に対応する |
| 退職者管理 | 可能 | なし。ただし管理者限定にする場合はログイン／権限が必要 |
| 権限による画面制御 | 不可 | ログイン／ログアウト機能が必要 |
| 詳細画面及び画面遷移改善 | 一部可能 | ログインユーザー名リンクやボタン制御はログイン／権限が必要 |

## 設計書の読み方

各追加機能の設計書には、次の項目を記載する。

1. 機能概要
2. 実装範囲
3. 前提条件・依存関係
4. 画面仕様
5. 処理仕様
6. データ仕様
7. 他機能と結合する場合の追加対応
8. 完了条件
9. テスト観点

## 対象ソース一覧について

本設計書では、変更対象ソースの一覧は原則として記載しない。

理由は、受講者が選択する追加機能や実装順序によって、実際に編集するファイルが変わるためである。
必要に応じて、Controller、Service、Repository、Entity、Form、HTML のどこに責務を置くかを設計内容から判断する。

## 評価の考え方

評価は「追加機能ごとの完成度」で行う。
すべての追加機能を結合して完成しているかだけではなく、各機能が単独でどこまで動作するかを確認する。

他機能との結合部分は、該当する依存機能を実装した場合のみ評価対象とする。

## 担当別の実装範囲例

チームで作業する場合は、次のように担当を分けると進めやすい。
ただし、実装順序や進捗によって担当範囲を調整してよい。

| 担当 | 内容 |
| --- | --- |
| ログイン・ログアウト担当 | ログイン画面、入力チェック、認証、セッション管理、ログアウト、ログインユーザー名表示 |
| デザイン担当 | 共通レイアウト、検索結果のレスポンシブ対応、一覧・詳細画面の見た目調整、顔写真表示 |
| 権限管理担当 | `role` の追加、管理者／一般ユーザーの表示制御、管理者用メニュー、操作ボタン制御 |
| 画面遷移改善担当 | 一覧・検索結果から詳細画面への遷移、ログインユーザー名クリックによる本人詳細遷移、ログイン画面から登録画面への導線 |
| 退職者管理担当 | `deleteFlg` の追加、論理削除、退職者一覧、復元、完全削除、通常検索からの退職者除外 |
