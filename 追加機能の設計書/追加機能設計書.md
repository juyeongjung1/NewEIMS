# EIMS 追加機能設計書

## 1. 追加機能一覧

| No. | 追加機能 | 主な内容 |
| --- | --- | --- |
| 1 | ログイン／ログアウト機能 | ログイン画面、入力チェック、認証、セッション管理、ログアウト |
| 2 | デザイン改良 | 共通レイアウト、Bootstrap 調整、検索結果の見やすさ改善、一覧画面に顔写真表示 |
| 3 | 退職者管理 | `deleteFlg` による論理削除、退職者一覧、復元、完全削除 |
| 4 | 権限による画面制御 | `role` による管理者／一般ユーザーの表示・操作制御 |

## 2. 実装順序と依存関係

共通機能の演習ガイドに沿った実装が完了している状態から開始する。

一部の追加機能は、他の追加機能に依存する。
依存する機能が未実装の場合は、該当箇所を省略して実装してよい。

| 追加機能 | 単独実装 | 依存する機能 |
| --- | --- | --- |
| ログイン／ログアウト | 可能 | なし |
| デザイン改良 | 可能 | なし。ただしログイン表示や権限メニューは他機能と結合時に対応する |
| 退職者管理 | 可能 | なし。ただし管理者向けに表示する場合はログイン／権限が必要 |
| 権限による画面制御 | 不可 | ログイン／ログアウト機能が必要 |
| 詳細画面及び画面遷移改善 | 一部可能 | ログイン中社員名リンクはログイン、ボタン制御は権限、退職状態表示は退職者管理が必要 |

## 3. 分担実装の進め方

複数人で同時に実装する場合は、各担当が単独で進められる範囲を先に実装し、依存する部分は結合時に追加する。

| 追加機能 | 先に進められる範囲 | 結合時に合わせる範囲 |
| --- | --- | --- |
| ログイン／ログアウト | ログイン画面、認証、セッション保存、ログアウト | 共通レイアウトのヘッダー表示、権限判定、退職者ログイン不可 |
| デザイン改良 | 共通レイアウト、一覧・検索結果の表、一覧画面の顔写真表示 | ログイン状態表示、管理者メニュー、退職状態・権限表示 |
| 退職者管理 | `deleteFlg`、退職者一覧、復元、完全削除 | 管理者だけにメニューや操作ボタンを表示する制御 |
| 権限による画面制御 | `role`、管理者／一般ユーザー判定 | ログイン中社員情報、退職者管理、詳細画面の操作ボタン |
| 詳細画面及び画面遷移改善 | 詳細画面の顔写真、権限・退職状態表示 | ログイン中社員名リンク、本人判定、変更・退職処理ボタン制御 |

同じ画面を複数の担当者が変更する場合は、次の順で結合すると確認しやすい。

1. ログイン情報をセッションに保存できる状態にする。
2. 共通レイアウトを各画面へ適用する。
3. 退職者管理の `deleteFlg` を画面表示と検索条件に反映する。
4. 権限管理の `role` をメニューと操作ボタンに反映する。
5. 詳細画面に、ログイン中社員リンク、顔写真、権限、退職状態、操作ボタン制御を反映する。

画面レイアウト図は、該当機能だけを実装した段階と、他機能を追加した後の段階を分けて確認する。
特に追加機能2は、追加機能3や4を実装する前後で表示項目が変わる。

# 追加機能1 ログイン／ログアウト機能

## 1.1 機能概要

社員番号とパスワードを使ってログインできるようにする。
ログイン成功時は、ログイン中の社員情報をセッションに保持する。
ログアウト時はセッションを破棄し、ログイン画面へ戻る。

## 1.2 実装範囲

- ログイン画面を表示する
- 社員番号とパスワードの入力チェックを行う
- DB上の社員情報と照合して認証する
- ログイン成功時にセッションへログイン社員情報を保存する
- ログイン失敗時にエラーメッセージを表示する
- ログアウト時にセッションを破棄する

## 1.3 前提条件・依存関係

この機能は単独で実装可能である。

ただし、以下の追加機能ではログイン情報を利用するため、この機能が前提になる。

| 関連する追加機能 | 関係 |
| --- | --- |
| 権限による画面制御 | ログイン中社員の `role` を使って管理者かどうか判定する |
| 退職者管理 | 退職済み社員をログイン不可にする場合、`deleteFlg` を参照する |
| デザイン改良 | 共通レイアウトのヘッダーにログイン状態を表示する |
| 詳細画面及び画面遷移改善 | ヘッダーのログイン中社員名から本人詳細へ遷移する |

## 1.4 画面仕様

### ログイン画面

| 項目 | 内容 |
| --- | --- |
| 社員番号 | 数値入力 |
| パスワード | パスワード入力。必須、4文字以上16文字以内 |
| ログインボタン | 入力内容を送信する |
| エラー表示 | 入力チェックエラー、または認証失敗時に表示する |

### ログイン後の表示

ログイン成功後は、共通レイアウトのヘッダー右上にログイン中社員の氏名を表示する。
表示形式は「ようこそ、氏名さん」とし、氏名の横にログアウトボタンを配置する。

ログアウトボタンを押すとログアウト処理を行い、セッションを破棄してログイン画面へ戻る。

デザイン改良の共通レイアウトをまだ実装していない段階では、ヘッダー右上の表示は作成できない。
その場合は、ログアウト処理だけを先に実装し、共通レイアウト結合時にヘッダー表示とボタン配置を追加する。

## 1.5 処理仕様

### ログイン処理

※退職済み社員をログイン不可にする仕様は、追加機能3の退職者管理を実装してからを前提にする。

1. 社員番号とパスワードを受け取る。
2. 入力チェックを行う。
3. 社員番号で社員情報を取得する。
4. パスワードが一致するか確認する。
5. 退職者管理を実装している場合は、`deleteFlg = 0` の社員のみログイン可とする。
6. 認証成功時は、社員情報をセッションに保存してトップページへ遷移する。
7. 認証失敗時は、ログイン画面へ戻し、エラーを表示する。

### ログアウト処理

1. ログアウト操作を受け取る。
2. セッションを破棄する。
3. ログイン画面へリダイレクトする。

## 1.6 データ仕様

この機能単独では、新しいテーブルや列は必須ではない。
既存の社員番号とパスワードを利用する。
パスワードの入力規則は共通機能と同じく、4文字以上16文字以内とする。

退職者管理と結合する場合は、社員情報の `deleteFlg` を参照する。
権限管理と結合する場合は、社員情報の `role` をセッション上でも参照できるようにする。

## 1.7 他機能と結合する場合の追加対応

| 結合する機能 | 追加対応 |
| --- | --- |
| デザイン改良 | 共通レイアウトのヘッダーにログイン中社員名、ログアウトボタン、未ログイン時のログインボタンを表示する |
| 権限による画面制御 | ログイン成功時に保存した社員情報の `role` を使って表示制御する |
| 退職者管理 | `deleteFlg = 1` の社員はログイン失敗扱いにする |
| 詳細画面及び画面遷移改善 | ヘッダーのログイン中社員名を本人詳細画面へのリンクにする |

## 1.8 完了条件

- 正しい社員番号とパスワードでログインできる
- 誤った社員番号またはパスワードではログインできない
- 入力チェックエラーが画面に表示される

※画面右上のログイン中表示は、追加機能2の共通レイアウトを実装してからを前提にする

- ログイン成功後、画面右上に「ようこそ、氏名さん」とログアウトボタンが表示される
- ログアウト後、ログイン画面へ戻り、画面右上のログイン中表示が出なくなる

## 1.9 テスト観点

| 観点 | 確認内容 |
| --- | --- |
| 正常系 | 正しい社員番号とパスワードでログインできる |
| 異常系 | 未入力、桁不足、不一致時にログイン画面へ戻る |
| セッション | ※追加機能2の共通レイアウト実装後、ログイン後に画面右上へログイン中社員の氏名が表示される |
| ログアウト | ※追加機能2の共通レイアウト実装後、ログアウトボタン押下でログイン画面へ戻りログイン中表示が消える |
| 結合 | 権限管理やヘッダー表示でログイン社員情報を利用できる |

# 追加機能2 デザイン改良

## 2.1 機能概要

画面全体の見た目と使いやすさを改善する。
共通レイアウトを導入し、ヘッダー、サイドバー、メイン領域の構成をそろえる。
検索結果や一覧画面では、社員情報を見やすく表示する。

## 2.2 実装範囲

- 共通レイアウトを作成する

- 一覧画面に、社員番号に対応する顔写真を表示する

## 2.3 前提条件・依存関係

## 2.5 処理仕様

### 共通レイアウト適用

1. 共通レイアウトを作成する。
2. 各画面の本文部分を共通レイアウトに差し込む。
3. 画面ごとの差分は、メイン領域に記述する。

### 顔写真表示

顔写真は、あらかじめ静的ファイルとして用意されている画像を表示する。

画像ファイルは、`src/main/resources/static/images` フォルダに配置する。
このフォルダには、社員番号と同じファイル名の PNG 画像が 60 件入っている。

ファイル名の例は次の通りである。

| 社員番号 | 画像ファイル |
| --- | --- |
| 10001 | `/images/10001.png` |
| 10002 | `/images/10002.png` |
| 10060 | `/images/10060.png` |

一覧画面に顔写真を表示する際は、行の高さが大きく崩れないように固定サイズを指定する。
検索結果や一覧画面では、幅 60px、高さ 70px 程度を目安とする。

## 2.6 データ仕様

この機能単独では、新しいDB項目は不要である。

顔写真はDBではなく、静的ファイルとして管理する。
画像ファイルは `src/main/resources/static/images` フォルダに配置する。
ファイル名は社員番号と同じ値にし、拡張子は `.png` とする。

例:

- `10001.png`
- `10002.png`
- `10060.png`

# 追加機能3 退職者管理

## 3.1 機能概要

社員削除を物理削除ではなく論理削除に変更する。
退職者は通常の検索結果や在籍者一覧には表示せず、退職者一覧で確認できるようにする。
退職者一覧では、復元と完全削除（物理削除）を行えるようにする。

本書では、通常画面で社員を退職状態にする操作を「退職処理」、`deleteFlg` を更新するDB処理を「論理削除」、DBからレコードを削除する処理を「完全削除（物理削除）」と呼ぶ。

共通機能で作成した削除機能は、削除ボタン押下後にDBから社員レコードを直接削除する処理になっている。
追加機能3では、この削除処理を修正し、DBから直接削除せずに `deleteFlg` を `1` に更新する。
通常の社員一覧と検索結果では `deleteFlg = 0` の社員だけを表示し、`deleteFlg = 1` の社員は退職者管理画面で確認する。

## 3.2 実装範囲

- 社員情報に退職者フラグを追加する
- 削除処理を論理削除に変更する
- 通常検索では退職者を除外する
- 退職者一覧を表示する
- 退職者を在籍者へ復元する
- 退職者を完全削除する

## 3.3 前提条件・依存関係

この機能は単独で実装可能である。

ただし、退職者管理を管理者向けに表示する場合は、ログイン／権限機能が必要である。

| 関連する追加機能 | 関係 |
| --- | --- |
| ログイン／ログアウト | 退職済み社員をログイン不可にする場合に利用する |
| 権限による画面制御 | 退職者一覧、復元、完全削除のメニュー・ボタンを管理者だけに表示する |
| デザイン改良 | 退職者一覧に共通レイアウトを適用する |
| 詳細画面及び画面遷移改善 | 詳細画面に退職状態を表示する |

## 3.5 処理仕様

### 論理削除

共通機能で実装した削除処理を修正する。
共通機能ではDBに対して `delete` を実行し、社員レコードを直接削除していた。
追加機能3ではDBに対して `update` を実行し、対象社員の `deleteFlg` を `1` にする。

1. 削除対象の社員番号を受け取る。
2. 対象社員を取得する。
3. 対象社員の `deleteFlg` を `1` に更新する。
4. 社員レコードはDBに残したままにする。
5. 削除完了画面を表示する。

### 通常検索

1. 社員番号、氏名、部署で検索する。
2. 通常検索では `deleteFlg = 0` の社員だけを対象にする。
3. 退職者は通常検索結果に表示しない。

社員一覧画面でも同様に、`deleteFlg = 0` の社員だけを表示する。
これにより、退職処理済みの社員は通常の一覧・検索結果から見えなくなる。

#### 社員一覧で退職者を除外する方法

本教材の標準実装は、共通機能の `findAll()` を変更せず、Thymeleaf の `th:if="${employee.deleteFlg == 0}"` で在籍社員の行だけを表示する方法とする。これは、共通機能で学習した `th:if` を使って実装できるためである。

通常検索では、氏または名の部分一致検索の対象から退職者を除外する。これは、社員一覧で在籍社員の行だけを表示する処理とは用途が異なる。

### 退職者一覧

1. `deleteFlg = 1` の社員を取得する。
2. 退職者一覧画面に表示する。

通常の一覧・検索結果から除外された退職者を確認するために、退職者管理画面を追加する。
この画面では、退職者の確認、復元、完全削除を行う。

### 復元

1. 復元対象の社員番号を受け取る。
2. 対象社員の `deleteFlg` を `0` に更新する。
3. 退職者一覧へ戻る。

### 完全削除

※完全削除は、追加機能3で追加する退職者管理画面から実行する。

1. 完全削除対象の社員番号を受け取る。
2. 対象社員をDBから物理削除する。
3. 退職者一覧へ戻る。

## 3.6 データ仕様

社員情報に次の項目を追加する。

| 項目 | 内容 |
| --- | --- |
| `deleteFlg` | 0: 在籍、1: 退職 |

初期値は `0` とする。

| 詳細画面及び画面遷移改善 | 詳細画面に退職状態を表示する |

## 3.8 完了条件

- 社員削除時にレコードが消えず、`deleteFlg` が `1` になる
- 共通機能の削除処理が、物理削除ではなく論理削除に修正されている
- 通常検索に退職者が表示されない
- 社員一覧に退職者が表示されない

# 追加機能4 権限による画面制御

## 4.1 機能概要

一般ユーザーには検索、登録、参照、および本人情報の変更を表示する。他社員の変更、退職処理、全社員一覧、退職者管理は表示しない。

## 4.2 実装範囲

# 追加機能5 詳細画面及び画面遷移改善

- 詳細画面に顔写真を表示する
- 詳細画面に権限を表示する
- 詳細画面に退職状態を表示する
- 詳細画面の変更ボタン、退職処理ボタンを権限に応じて表示制御する

この機能は、共通機能で社員詳細画面が作成済みであることを前提とする。
また、一覧画面や検索結果画面から社員詳細画面へのリンクも作成済みであることを前提とする。

## 5.5 処理仕様

※ログイン中社員名リンクは追加機能1と2、顔写真表示は追加機能2、退職状態表示は追加機能3、操作ボタンの表示制御は追加機能4を実装してからを前提にする。

### ログイン中社員名リンク

※追加機能1のログイン／ログアウトと、追加機能2の共通レイアウトを実装してからを前提にする。

1. セッションからログイン中社員情報を取得する。
2. ヘッダーにログイン中社員名を表示する。
3. 社員名に本人詳細画面へのリンクを設定する。
4. クリック時、ログイン中社員の社員番号を使って詳細画面へ遷移する。

### 詳細画面の追加表示

※顔写真は追加機能2、退職状態は追加機能3、権限表示は追加機能4を実装してからを前提にする。

1. 詳細表示対象の社員情報を取得する。
2. 社員番号を使って顔写真の画像パスを組み立てる。
3. `role` を表示用の文言に変換する。
4. `deleteFlg` を表示用の文言に変換する。
5. 詳細画面に顔写真、権限、退職状態を表示する。

### 操作ボタンの表示制御

※追加機能4の権限による画面制御を実装してからを前提にする。

1. セッションからログイン中社員情報を取得する。
2. ログイン中社員の `role` を確認する。
3. ログイン中社員番号と表示対象社員番号を比較する。
4. 管理者、本人、他人の条件に応じて、変更ボタンと退職処理ボタンを表示する。

## 5.6 データ仕様

この機能で新しいDB項目は追加しない。

次の既存項目、または他の追加機能で追加した項目を利用する。

| 項目 | 利用目的 |
| --- | --- |
| `empNo` | 顔写真ファイル名、本人判定、詳細画面遷移 |
| `lastName` / `firstName` | ヘッダー表示 |
| `role` | 権限表示、変更・退職処理ボタンの表示制御 |
| `deleteFlg` | 退職状態表示 |

## 5.7 他機能と結合する場合の追加対応

| 結合する機能 | 追加対応 |
| --- | --- |
| ログイン／ログアウト | ログイン成功時にセッションへ保存した社員情報を利用する |
| デザイン改良 | 顔写真の配置場所と表示サイズをそろえる |
| 退職者管理 | `deleteFlg` を使って退職状態を表示する |
| 権限による画面制御 | `role` を使って変更・退職処理ボタンを表示制御する |

## 5.8 完了条件

※ヘッダーのログイン中社員名リンクは追加機能1、2を実装してから確認する

- ヘッダーのログイン中社員名をクリックすると、本人詳細画面へ遷移できる

※顔写真表示は追加機能2を実装してから確認する

- 詳細画面に社員番号に対応する顔写真が表示される

※権限表示は追加機能4、退職状態表示は追加機能3を実装してから確認する

- 詳細画面に権限が表示される
- 詳細画面に退職状態が表示される

※操作ボタンの表示制御は追加機能4を実装してから確認する

- 管理者、本人、他人の条件に応じて、変更・退職処理ボタンの表示が変わる
